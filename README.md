# Multi-Horizon Streamflow Forecasting with a Cluster-Specific Temporal Fusion Transformer

A PyTorch Lightning implementation of a **Temporal Fusion Transformer (TFT)** for multi-horizon streamflow forecasting (1, 3, 7, 14, and 30-day lead times) across **206 river basins in India**, grouped into hydro-climatic clusters and trained with cluster-specific and global model variants.

## Overview

Forecasting streamflow at multiple lead times is central to flood early-warning and water-resources planning, but a single global model often underperforms on basins with distinct hydro-climatic behavior. This project trains a TFT — a sequence-to-sequence architecture combining LSTM encoders/decoders, gated residual networks (GRNs), variable-selection networks, and interpretable multi-head attention — separately per basin cluster, and compares cluster-specific skill against a global (all-basins) baseline.

**Key components:**

- **`ClusterTFT`** — the core model: static covariate encoding, past/future variable-selection networks (VSNs), an LSTM encoder-decoder, a causal-masked multi-head attention block over the combined encoder/decoder sequence, and three quantile heads (0.1 / 0.5 / 0.9) for probabilistic forecasts.
- **Corrected attention mask** — the notebook fixes a boolean causal mask that previously produced an invalid `0 × -inf` operation and caused NaN predictions; the mask is now built explicitly as a boolean "don't attend" matrix restricted to the decoder region.
- **`HydroScaler`** — per-basin (and global) feature/target scaling with log1p-transformed streamflow and masked loss computation so that missing observations don't corrupt gradients.
- **`BasinTensorStore`** — a memory-efficient, index-based `Dataset` that avoids materializing every basin's full windowed tensor set at once.
- **Masked quantile + NSE-weighted loss** — a composite loss (`W_NSE=0.7`, `W_Q=0.3`) combining a flow-weighted Nash-Sutcliffe term with pinball/quantile loss, so the model is pushed toward both overall fit and calibrated uncertainty.
- **Evaluation** — NSE, KGE, flow-weighted NSE (wNSE, emphasizing flood peaks), and CSI at a high-flow threshold (Q90), computed per basin/cluster/lead time.

## Data

The notebook expects a `prepared_data` directory (per-basin time series + a `feature_config.json`) laid out for Kaggle (`/kaggle/input/.../prepared_data`), with automatic fallback discovery (`resolve_data_root()`) so it also runs from a local working directory outside Kaggle. Dynamic past inputs are `streamflow, precip, tmax, tmin, pet`; dynamic future (known) inputs are `precip, tmax, tmin, pet`; basin static attributes (~54 features) are also used. Data itself is not included in this repository — only the modeling code.

## Results (example run)

A representative run on the **global (all-basins) cluster** — 206/206 basins loaded, ~1.50M training windows / 521K validation / 445K test samples, 1.0M-parameter model, trained with 16-bit AMP on a single GPU — showed steadily improving validation loss (best score 73.7 → 7.6 over the early epochs) with no NaNs in predictions or inputs at the preflight diagnostic stage. Forecast skill (NSE, KGE, wNSE, CSI) is computed and plotted against lead time (1/3/7/14/30 days) for each cluster against the global baseline; see `forecast_skill_comparison.png`-style output generated by the final plotting cell when run end-to-end.

Exact metric values depend on the dataset used and are written to `*_results.csv` / `*_median_summary.csv` by the notebook — they are not checked into this repository since no training data is included here.

## Running it

1. **Data**: place a `prepared_data` folder (with `feature_config.json` and per-basin series) somewhere discoverable, or set `DATA_ROOT` in the configuration cell to its path.
2. **Environment**: `pip install -r requirements.txt` (a CUDA-capable GPU is strongly recommended — training on CPU is impractical given dataset size).
3. **Run**: execute the notebook top to bottom. Start with `MAX_EPOCHS = 5` and a single cluster to validate the pipeline before scaling up to full training across all clusters.
4. **Outputs**: per-cluster result CSVs, a combined results CSV, a median-metric summary CSV, and a forecast-skill comparison figure are written to the configured output directory.

Originally developed and run on **Kaggle** (GPU accelerator); the data-path resolution logic also supports running locally.
